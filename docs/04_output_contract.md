# OwlPath 开发结果合同 v3

当前 Schema：`owlpath.result.v3`  
适用模式：纯虚构或已去标识化的开发推演  
临床状态：未验证、未校准、不是医疗器械

## 1. 当前结果页顺序

结果页的首屏依次展示：

1. 运行身份条：运行 ID、状态、Provider、模型和版本；
2. 具体病原体 Top-5；
3. 病原体总诊摘要；
4. 下一项检查；
5. 病原大类、Unknown、共感染、文献证据和 Agent 摘要；
6. 本次运行轨迹；
7. 页面底部折叠的“开发诊断”，包括适用范围、OOD、时间、资料矛盾和校准告警。

页面固定提示：

> 开发推演，分数未校准；告警记录但不阻断。

## 2. 开发结果的三种状态

### `completed`

真实 Agent 链完成，确定性合同有效，结果包含恰好 5 个具体病原体。

### `completed_with_warnings`

Top-5 合同仍然有效，但运行存在非阻断情况，例如文献检索部分不可用、单个专科调用曾经切换 Provider、审稿提出并完成一次修订，或存在开发观察告警。

### `technical_failure`

技术上无法形成满足合同的结果，例如所有专科 Agent 都失败、总诊返回不可解析结果、数据完整性校验失败、硬超时，或者经过一次修订和透明候选池回退后仍不足 5 个可验证病原体。

技术失败不得发布不完整 Top-5，也不得用“细菌、病毒”等大类伪造补位。它只说明本次系统运行没有完成，不等于临床判断。

开发 v3 不包含临床 `safety_action`，也不使用 `abstain` 或“转人工”来绕过结果合同。

## 3. 具体 Top-5 合同

每个完成结果必须满足：

- `concrete_pathogens` 恰好 5 项；
- `rank` 为唯一且连续的 1、2、3、4、5；
- `canonical_latin_name` 是具体物种、物种复合群或明确病毒型别；
- 拉丁名和 `ncbi_taxonomy_id` 在本次 Top-5 中唯一；
- “细菌、病毒、真菌、寄生虫、未知病原、其他病原”等类别词禁止进入 Top-5；
- `model_score` 为 0–1 的未校准排序分数，并按非递增顺序排列；
- 每项至少有一条带真实 `source_fragment_id` 的支持证据；
- 记录反对证据、入选原因、主要不确定性和提出它的专科 Agent；
- 中英文名称来自版本化术语表或可验证的规范名称，不可靠的中文翻译不得猜测。

`unknown_score`、`category_overview` 和 `coinfection_hypotheses` 是独立字段，不与 Top-5 混用。

## 4. 确定性验证、审稿和修订

总诊 Agent 的 JSON 不是最终真相。后端确定性验证器检查：

- 是否恰好 5 个；
- 是否出现病原大类、属级模糊词或重复名称；
- 排名和分数是否一致；
- 来源片段引用是否真实存在；
- 每项是否有专科 Agent 来源；
- 名称是否可由本地术语缓存或 NCBI Taxonomy 解析。

独立审稿 Agent 再对照完整原文、核心与本次已选动态专病意见、外部证据元数据和本地验证问题，检查重要病例事实是否被静默遗漏。它不直接修改排名，只返回问题码和需要修改的内容。

若任一环节不合格，总诊最多修订一次。修订仍不合格时：

1. 只收集核心与本次已选动态专病 Agent 已经提出并通过术语验证的具体候选；
2. 按独立 Agent 支持数、平均支持分数和证据完整度透明排序；
3. 候选达到 5 个则完成，并标记 `fallback_mode=agent_pool_fallback`；
4. 候选不足 5 个则返回 `technical_failure`。

系统不能从一个与病例无关的通用病原词表中“凑够五个”。

## 5. 双语字段

核心文本使用：

```json
{
  "zh_cn": "中文主行",
  "en": "English secondary line",
  "status": "complete"
}
```

同一次 LLM 调用同时生成中英文和一套共享数值，不进行额外翻译调用。双语范围至少包括：

- 总诊摘要；
- 综合征名称；
- Top-5 病原体名称；
- 每项候选的入选原因和主要不确定性；
- 下一项检查名称和理由；
- 专科、检索、总诊和审稿的核心摘要。

如果某一语言缺失，预测结构仍可保留，字段标记为 `partial` 并在网页说明“另一语言未返回”。详细技术警告、文献标题和安全 JSON 可以保持原始语言。

## 6. 模型分数不是临床概率

`model_score` 只用于本次候选排序。它尚未在目标医院、目标人群或时间外队列中完成校准，所以页面必须写：

```text
模型分数 / Model score：0.30
```

不能写成“30% 概率”，不能把五项强制归一化后冒充真实概率，也不能根据分数直接给出用药建议。只有未来经过预注册、独立验证和发布评审的校准制品，才可能使用“校准概率”这一术语。

## 7. 证据与文献引用

病例证据使用稳定 `source_fragment_id`，每条支持或反对证据应说明：

- 证据来自哪个病例片段；
- 支持或反对哪个候选；
- 一句简短的医学解释；
- 提出该证据的 Agent 角色。

联网来源记录来源数据库、题名、标识符、链接和检索时间；同一 PMID/DOI 的 Europe PMC 与 PubMed 记录合并为一项发布证据，同时保留来源轨迹。候选特异绑定会排除题名仅显示鱼类、水产、兽医或动物实验语境且没有明确人体锚点的记录，但这仍只是题名元数据过滤。Europe PMC/PubMed/WHO DON 任一检索源失败时，结果可完成，但必须保留 `retrieval_partial` 警告；没有检索命中不能伪装成“已有文献证实”，WHO DON 未命中也不能推断“没有流行”。

## 8. 下一项检查

`next_tests` 是研究性的“信息价值”排序，不是自动医嘱。每项包含中英文名称、为什么可能区分当前候选，以及它预计解决的主要不确定性。系统不得生成药物名称、剂量、疗程、停药或自动写回医嘱。

## 9. 轨迹、版本与完整性哈希

每次结果至少绑定：

- 结果、执行图和轨迹版本；
- 运行 ID 与输入快照哈希；
- 冻结 Provider、模型和配置哈希；
- 每个节点的状态、尝试次数、耗时和安全输入输出哈希；
- 最终 `result_sha256`。

SHA-256 是内容完整性指纹，不是数字签名，不证明结果来源身份或医学正确性。

## 10. 与严格临床旧合同的关系

严格临床分支保留 `infection_unlikely / species_set / category_only / more_information_needed / abstain` 五态，以及时间闸门、医生复核、适用范围、校准和安全裁决。它目前不进入普通网页流程。

开发 v3 固定具体 Top-5 和“告警不阻断”只用于工程联调和研究观察，不能覆盖未来严格临床发布规则。临床发布仍需回顾性时间验证、外部多中心验证、校准、亚组评价和前瞻静默运行。

## 11. 固定声明

> 本结果仅用于竞赛展示、软件开发和方法学研究，尚未完成临床有效性验证，不是医疗器械，不可作为真实患者的独立诊断、检查医嘱或治疗依据。
