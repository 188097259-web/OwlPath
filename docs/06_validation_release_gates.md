# 验证、监测与发布门槛 v1

> **模式说明（2026-08-09）**：开发 v3 为了先跑通系统，要求完成结果给出具体 Top-5，并将范围/OOD/校准记录为观察告警。本文描述的是走向临床研究和发布时必须恢复并验证的严格门槛；开发合同通过不等于临床门槛通过。

## 1. 总原则

OwlPath 只有在已知范围内经过分阶段验证，才能从可运行研究版产品逐步走向真实临床研究。任何一个模型在单一数据集上取得较高 AUC 或 Top-5 召回率，都不足以证明它可以临床使用。

下文的数值门槛是建议的研究版准入线，不是已经获得临床证实的标准。正式研究必须在查看测试结果之前预注册主要终点、界值和非劣效/优效假设。

当前默认发布包尚无经过目标医院和目标人群验证的校准器，所以严格临床分支的物种级发布门槛未满足。开发 v3 显示的 Top-5 是未校准研究候选，不能视作物种级临床发布。历史合成样例中的 `species_set` 也只检查 Schema 分支，不计作性能、校准或临床验证证据。

## 2. 五个验证阶段

### 阶段 A：工程与合成数据验收

目标：证明系统按契约运行，而不是证明临床有效。

必须通过：

- 开发 `owlpath.result.v3`、`owlpath.execution-graph.v4` 和 `owlpath.trace.v2` Schema 验证 100%；
- 完成结果恰好返回 5 个具体、唯一、Taxonomy 可解析的病原体，大类词占据 Top-5 的比例为 0；
- 每个候选均能追溯到真实病例来源片段和至少一个专科 Agent；
- 文献检索离线时运行仍可完成并明确标记 `retrieval_partial`；
- 首轮只返回类别、少于 5 项或遗漏关键暴露时，审稿能够发现并触发最多一次修订；
- 修订仍不合格时只使用透明专科候选池，候选不足不得用通用词表补齐；
- 单 Provider、多 Provider、专科部分失败、总诊失败、审稿失败、硬超时和 SSE 续传都有测试；
- URL 中的 `run_id` 为页面读取依据，不同标签页、刷新和复制链接不得串运行；
- 禁止的用药、剂量、疗程和自动医嘱字段为 0；
- 严格临床回归测试继续覆盖时间泄漏、OOD、五态输出、粒度降级和弃答，证明开发分支没有改写其安全契约；
- 关键安全红队不得成功外传 API Key、病例到搜索引擎、跨病例污染或篡改完整性哈希。

### 阶段 B：回顾性内部与时间验证

目标：在单一开发机构中，检查模型对后续时间段的表现。

必须：

- 以患者/就诊为单位切分，同一病例的多个 `t` 快照不得跨训练集和测试集；
- 使用真实时间切分，不仅使用随机切分；
- 在预定的 `t_initial`、`t_labs`、`t_imaging` 或 `t_pre_microbiology` 锚点分别报告，不得事后挑选最好时点；
- 数据管道、标签仲裁和性能评价尽可能盲法分离；
- 保留检查不足、病原未知和非感染病例，不只分析确诊阳性病例。

### 阶段 C：外部多中心验证

目标：检查不同医院、人群、季节、检测平台和病原谱下的可迁移性。

必须：

- 开发机构数据不得参与外部测试的重新训练；
- 在查看结局前冻结模型和主要分析计划；
- 如仅允许本地概率校准，必须将校准集与最终测试集分开；
- 报告每家医院、总体和关键亚组结果，不得只报告合并平均值。

### 阶段 D：前瞻性静默运行

目标：在真实工作流中生成结果，但不向临床医生展示，不影响患者诊疗。

必须评价：

- 实际数据延迟和事件可见时间是否可靠；
- 每个 `t` 快照是否真实对应当时的可见证据；
- 弃答、需要更多信息和 OOD 比例；
- 本地先验和校准的漂移；
- 运行延迟、失败恢复、审计完整性和资源消耗。

### 阶段 E：人机协作与临床影响研究

只有 A–D 通过后才可考虑。必须有独立伦理、临床安全、数据安全和相应监管路径评估。

建议比较：

- 医生独立判断；
- 研究系统独立输出；
- 医生+研究系统协作。

重点不只是预测正确率，还包括自动化偏倚、不必要检查、时间、工作量、医生覆盖AI建议的能力和安全事件。

## 3. 必须报告的指标

### 3.1 感染/非感染层

- AUROC 和更重要的 AUPRC；
- 预定阈值下的灵敏度、特异度、PPV、NPV；
- Brier score、log loss、校准截距/斜率和校准图；
- 非感染性重要模拟疾病的错误强制病原率。

### 3.2 病原体层

- 宏平均和微平均 AUPRC/F1；
- Top-1、Top-3、Top-5 召回率；
- 层级正确率：大类、属、种；
- 共感染灵敏度和阳性预测值；
- unknown 和候选目录外病原的识别；
- 每个常见病原和关键罕见病原的独立结果。

### 3.3 不确定性和安全层

- ECE 和分类别校准；
- 预测集合的实际覆盖率、平均集合大小和亚组覆盖率；
- risk-coverage 曲线；
- OOD 检测灵敏度、特异度和错误接受率；
- `infection_unlikely`、`species_set`、`category_only`、`more_information_needed`、`abstain` 的比例和准确性；
- 严重数据冲突、未来泄漏和安全攻击的阻断率。

### 3.4 下一项信息/检查

- 推荐是否来自经审核白名单；
- 在真实结果揭盲后，该检查是否实际缩小了候选集合；
- 是否改变了研究性分类结论；
- 成本、时间、可获得性和侵入性的权衡；
- 无法获得时的回退行为。

### 3.5 Agent和工程层

- 完整轨迹的工具调用正确率；
- 平均和 P95 延迟；
- 超时、工具失败、恢复和弃答率；
- 同一快照重复运行的一致性；
- 证据陈述与原始事件的一致性；
- 安全攻击成功率、跨患者泄漏和禁止输出比例。

## 4. 研究版建议发布门槛

| 类别 | 建议门槛 | 不达标时 |
|---|---|---|
| 时间泄漏 | 自动和抽样人工审计均未发现禁止的当次 `t` 后信息 | 阻断发布 |
| Schema | 100% 预期输出通过 | 阻断发布 |
| 禁止临床指令 | 用药/剂量/自动医嘱输出为 0 | 阻断发布 |
| 校准 | ECE 原则上 <=0.05，校准斜率 0.8–1.2；且 Brier 不劣于预定基线 | 重新校准或限制范围 |
| 预测集合 | 观察覆盖率不低于预定目标减 2 个百分点，并报告95%CI | 放大集合或禁止物种级输出 |
| OOD | 定义好的 OOD 挑战集灵敏度原则上 >=0.90，严重 OOD 错误接受率 <=0.05 | 扩大弃答范围 |
| 亚组 | 无未解释的重大性能崩塌；主要指标绝对差原则上不超过 10 个百分点 | 限制适用范围或补充数据 |
| 参考基线 | 不仅与LLM比较；至少包括当地流行率、简单逻辑回归/GBDT和单模态模型 | 补充基线 |
| 红队 | 关键数据外泄、结果篡改、越权工具调用和绕过弃答成功次数为 0 | 阻断发布 |
| 可回滚性 | 在预定时间内可恢复上一稳定版本，且审计连续 | 阻断发布 |

上述门槛不代表通过后就可临床使用，只表示可以进入下一研究阶段。

## 5. 硬性阻断条件

出现任一条必须停止发布或立即回滚：

- 发现主要结果使用了当次 `t` 后信息、病原标签或出院诊断；
- 真实患者级数据被发送至未批准的外部系统；
- 存在跨患者记忆或身份信息暴露；
- 报告生成器修改了受完整性哈希保护的数值、隐藏弃答或生成治疗指令；
- 新版本在关键病原、关键亚组或严重病例中明显劣于已批准版本；
- 校准失效、本地先验过期或漂移超过门槛，但系统仍发布物种级结果；
- 工具、知识库、模型或配置版本/哈希不匹配；
- 审计日志不完整，无法追溯输出来源。

## 6. 发布与回滚流程

```text
开发候选版
→ 自动契约测试
→ 回顾性性能/校准/亚组评价
→ 安全红队
→ 临床、微生物、数据、安全多学科评审
→ 影子/灰度运行
→ 发布
→ 持续监测
→ 超阈值自动降级或回滚
```

每次发布必须形成一份不可变记录：谁批准、批准了什么、依据哪些评价、有哪些已知限制、何时需要重新审核。

## 7. 持续监测

至少监测：

- 输入分布、缺失率和单位变化；
- 病原大类、unknown、OOD和五种主状态的分布；
- 有标签结果到达后的校准和预测集合覆盖率；
- 不同医院、季节、年龄、性别和基础疾病亚组；
- 运行延迟、工具错误、弃答和人工覆盖率；
- 医生反馈、安全事件和错误模式。

未经审批，监测数据不得自动用于在线训练或替换正式模型。
