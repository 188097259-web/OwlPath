# 当前决策时点 `t` 与临床事件账本规范 v1

> **模式说明（2026-08-09）**：本文是严格临床分支和离线评价防时间泄漏的规范。普通网页当前的开发 v3 入口不要求医生设置 `t` 或完成结构化复核，但仍冻结创建运行时的完整输入快照。开发便利不能被用于宣称回顾性验证没有时间泄漏。

## 1. 当前决策时点 `t` 的临床含义

当前决策时点 `t` 是“医生此次点击运行系统的时刻”，不是固定的入院后若干小时，也不是某项检查或最终诊断的时刻。

每次运行时，系统只能看到截至当次 `t` 临床医生已经能够看到的信息。血液、影像或其他新信息到达后，医生可以在新的 `t` 再次运行，形成一条不可覆盖的动态快照序列：

```text
t1：初诊问诊后
t2：首批血液结果可见后
t3：影像报告可见后
t4：新的非确证性信息到达后
```

每张快照都只对应当时的知情状态。`t1` 之后才知道的结果不能回填 `t1`，但可在 `t2` 或更后的新运行中使用。

## 2. 严格临床 v1 的运行规则

产品运行规则是：

1. 医生在网页中设置带明确时区的当前 `decision_time`，粘贴截至该时点的去标识化临床大文本；无时区时间一律拒绝，不猜测为 UTC；
2. 本地确定性整理器生成结构化预览和时间/隐私/标签泄漏警告；整理接口不调用模型，也不持久化该请求；
3. 医生必须显式核对整理结果；原文或 `decision_time` 变化后，核对状态自动失效；
4. 医生单独点击启动，后端验证实时 `decision_time` 位于服务器当前时间前 15 分钟至后 1 分钟并冻结本次运行；启动动作不得隐式整理后直接运行；
5. 构建所有 `visible_at <= decision_time` 的经审核结构化事件快照，去标识化原文只作本地审计材料，不直接进入模型提示词；
6. 对当次 `decision_time` 之后的事件做显式排除并记录数量；
7. 快照、Provider 配置、治理配置、运行清单和输出生成可核对的完整性哈希；任何模型调用前再次核对，失败则在外发和计费前关闭；
8. 新信息到达后可再次运行，生成新的 `decision_time` 和新快照。

如事件与 `decision_time` 只有秒级精度且无法确认先后，应采取保守原则排除该事件。

## 3. 回顾性评测的阶段性锚点

回顾性研究时，不能真的“点击按钮”，因此可在方案中预定一个或多个阶段性锚点：

回顾模式不能借用临床实时入口绕过限制。当前 API 默认禁用 `retrospective`；只有服务器显式启用、管理员鉴权且提供预注册锚点 ID 时才接受，并在运行记录中永久标明模式和锚点。

| 锚点 | 示例定义 | 用途 |
|---|---|---|
| `t_initial` | 首次医生评估签署时 | 仅用问诊和生命体征的基础版 |
| `t_labs` | 预先指定的首批常规血液结果全部可见时 | 评估血液信息的增量价值 |
| `t_imaging` | 首份胸部影像报告签发时 | 评估影像报告的增量价值 |
| `t_pre_microbiology` | 首个可确定病原的结果可见前的最后快照 | 主要早期病原预测评估 |
| `t_6h` | 到院后 6 小时 | 某些研究方案的固定时间窗示例 |

到院+6小时只是可选锚点，不是 v1 唯一规则。主要分析使用哪些锚点必须在研究开始前写入方案，不得看到结果后再选择最好的时点。

## 4. 每个事件必须记录的时间

| 字段 | 含义 | 例子 |
|---|---|---|
| `occurred_at` | 事件真正发生的时间 | 患者 08:20 抽血 |
| `collected_at` | 标本采集时间，不适用时可为 null | 08:20 |
| `resulted_at` | 实验室/影像系统产生结果的时间 | 09:05 |
| `clinician_visible_at` | 结果真正进入临床界面、医生可查看的时间 | 09:08 |
| `recorded_at` | 事件写入研究账本的时间 | 09:09 |

判断能否用的核心是 `clinician_visible_at`，而不是抽血时间。

## 5. 事件账本最小字段

每个事件至少包含：

```json
{
  "event_id": "EVT-001",
  "event_type": "laboratory_result",
  "occurred_at": "2026-01-15T08:20:00+08:00",
  "collected_at": "2026-01-15T08:20:00+08:00",
  "resulted_at": "2026-01-15T09:05:00+08:00",
  "clinician_visible_at": "2026-01-15T09:08:00+08:00",
  "recorded_at": "2026-01-15T09:09:00+08:00",
  "source_system": "SYNTHETIC_LIS",
  "source_record_id": "SYN-LAB-001",
  "status": "final",
  "quality": "usable",
  "value": {"test": "WBC", "numeric": 12.4, "unit": "10^9/L"},
  "eligible_at_decision_time": true,
  "exclusion_reason": null
}
```

## 6. 事件类型

- `history_fact`：病史、暴露史、旅行史；
- `symptom`：症状及发生时间；
- `vital_sign`：生命体征和给氧状态；
- `laboratory_result`：常规血液结果；
- `imaging_report`：已签发的影像报告；
- `microbiology_result`：病原学结果；如在当次 `t` 前已可见，运行必须标记为 `post_microbiology_update`，不得混入“病原结果前早期预测”主要评价；
- `medication_exposure`：用药暴露，必须区分当次 `t` 前的已知暴露和 `t` 后的未来治疗；
- `procedure`：采样、插管等操作；
- `diagnosis_statement`：诊断文字，需防止出院诊断泄漏；
- `administrative`：到院、入院、转科等管理事件。

## 7. 当次 `t` 的可用性判定

一项事件必须同时满足所有条件才能使用：

1. `clinician_visible_at <= decision_time`，且不存在时间精度无法解决的先后争议；
2. 来源和记录可追溯；
3. 不属于出院诊断、后续专家仲裁或治疗反应；
4. 不包含病原学标签或可直接推回标签的文本；
5. 数值单位、状态和质量可解释；在线模型只接收项目白名单、标准单位和宽安全范围内的数值，未知单位不得透传；
6. 不是在病原学结果知情后才回填的病史摘要。

## 8. 缺失和否定不能混同

事件账本必须区分：

- `present`：明确存在；
- `explicitly_absent`：已询问且患者明确否认；
- `not_asked`：没有询问；
- `patient_unsure`：已询问但患者不确定；
- `not_tested`：未做该项检查；
- `pending`：已采样但当次 `t` 时结果尚未可见；
- `interface_missing`：可能已存在，但数据接口未提供；
- `not_applicable`：不适用。

“未记录禽类接触”不得编码为“明确无禽类接触”。

## 9. 冲突处理

如出现以下情况，不得静默选择其中一个：

- 医生记录“无发热”，护理体温 39.2℃；
- 两份检验报告单位不同且无法换算；
- 结构化用药史显示长期激素，自由文本写“无免疫抑制”；
- 影像报告与后续修订报告冲突。

系统应：

1. 保留所有原始事件；
2. 标记冲突的字段和来源；
3. 按事先版本化规则决定是否能解决；
4. 不能解决时降低数据质量等级；
5. 冲突涉及适用范围或关键证据时，降级或弃答。

## 10. 账本不可变与可追溯性

- 原始事件不得被覆盖；更正以新事件附加。
- 每次预测保存输入事件 ID 清单和只含 ID/原因的排除清单，不保存被排除事件的未来内容。
- 排除必须有原因，例如 `visible_after_decision_time`、`forbidden_label_leakage`、`invalid_unit` 或 `untrusted_source`。
- 每次运行必须记录时间规则版本和完整性哈希。哈希用于发现内容变化，不是数字签名，也不证明结论正确。

## 11. 研究评价时的分离

每个病例应存在两个逻辑上隔离的包：

```text
决策快照包：只有截至该次 decision_time 可见的信息，交给模型
最终标签包：允许使用后续病原学和专家仲裁，只用于评分
```

建议分别存储，并对每个决策快照包执行自动泄漏检测。任何无法确认时间边界的快照不得进入主要性能分析。同一病例的多个快照必须以患者/就诊为单位进行数据集切分，不得让同一患者的不同时点分别落入训练集和测试集。
